# アバターの動き: 調査と設計

音声アシスタントの VRM アバター（`apps/web/src/avatar/`）の体の動きを、ポーズを切り替えるだけの状態から、
つなぎ目を感じさせない動きにするための調査メモと、それを踏まえた設計。

## 1. 最初の実装で「つなぎ目」を感じた原因

最初の実装は「状態・表情ごとの静的なポーズ」を用意し、臨界減衰のばねで目標へ追従させていた。

1. **ポーズに届くと止まる** — 収まった後は、規則的な呼吸・揺れしか残らず、「ポーズを取って固まる」印象になる
2. **全身が同じ速さで一斉に動く** — 肩・ひじ・手首が同時に同じ速さで動き、人形のように見える
3. **角度を軸ごとに補間する** — 腕のねじりが大きく違うポーズ同士（腰に手 ⇔ 胸の前）で、腕が体を突き抜けるような経路を通る
4. **身振りに始まりと終わりの流れが無い** — 文ごとにポーズを切り替えるだけで、構えて・強調して・戻す流れが無い
5. **揺れが規則的** — 正弦波の揺れは周期が見えてしまう

## 2. 世の中の手法

| 手法 | 使われ方 | 要点 | このプロジェクトへの応用 |
|---|---|---|---|
| フェード付きのモーション切り替え | Live2D、Unity の Animator | 作られたモーションをフェードイン/アウトで切り替える。優先度（待機 < 通常 < 強制）で待機の動きに割り込む | VRMA（VRM Animation）＋ three.js の AnimationMixer で実現できる（→ 提案2） |
| レイヤーとマスク | Unity の Animator Layers | 全身の待機を土台に、上半身だけの身振りで上書きし、視線・呼吸は足し算で重ねる | 部位ごとに独立した層で動かす考え方を取り入れる |
| 慣性化（inertialization） | Gears of War、Unreal Engine | 新しい動きに即座に切り替え、前の姿勢との差を速度を保ったまま減衰させる | 目標の切り替えを「差を減衰させる」ものとして扱う点は、ばねで近いことをしている |
| ばね・2次系の動き | 手続き的アニメーション全般（Daniel Holden "Spring-It-On"、t3ssel8r "Giving Personality to Procedural Animations using Math"） | 臨界減衰のばねに、行き過ぎ（overshoot）や予備動作（anticipation）を足すと生き物らしくなる。2次系は「周波数 f・減衰 ζ・応答 r」の3値で性格を決められる | **採用**。関節ごとに f・ζ・r を変える |
| 身振りの段階 | 身振り研究（Kendon、McNeill） | 身振りは「準備 → ストローク（強調）→ 保持 → 戻す」。ストロークは言葉の強調とほぼ同時か少し前に来る | **採用**。VOICEVOX のアクセント位置で強調の時刻を決める |
| モーションマッチング | For Honor、The Last of Us Part II、UE5 | 大量のモーションDBから、いまの姿勢と次の目的に最も合う姿勢を毎コマ選ぶ | 大量のモーキャプ前提で過剰。「候補から今の姿勢に近いものを選ぶ」考え方だけ参考にする |
| 発話からの身振り生成 | ZeroEGGS（Ubisoft La Forge）、GENEA Challenge、BEAT2 | 音声・文章から全身の身振りを学習モデルで生成する。LLM の文章特徴を使うと質が上がるという報告もある | 研究段階で重く、gco の CPU（AVX 無し）でリアルタイムは非現実的（→ 提案3、将来） |
| LLM に動作を選ばせる | ChatVRM / AITuberKit（感情＋VRMA）、Convai、NVIDIA ACE | 会話AIが感情・動作名を出し、対応する動きを再生する | 実装済み（返答の（表情名）→ 表情・身振り） |

## 4. 設計（提案1）

### 4.1 2次系の動き（`dynamics.ts`）

t3ssel8r の2次系（second-order dynamics）で、各関節の各軸を目標に追従させる。

- `f`（周波数）: 目標へ向かう速さ
- `ζ`（減衰）: 1 で行き過ぎなし、1 未満で行き過ぎて戻る、0 で振動し続ける
- `r`（応答）: 0 でゆっくり動き出す、1 で即座に動き出す、1 より大きいと行き過ぎ、**負だと最初に反対へ動く（予備動作）**

目標が段階的に切り替わった瞬間の目標の速度を使うので、`r < 0` にするだけで「大きく動く前に少し反対へ動く」予備動作になる。

1コマが長いとき（描画の遅い端末、引っかかり）の扱い:

- k2 を安定な範囲に引き上げる（t3ssel8r の方法）だけでは、発散はしなくても大きな刻みで極端に行き過ぎる
  （4ms のコマの直後に 250ms のコマが来ると、上腕が目標 90 度に対して 162 度まで振れた）。
  そこで1コマを 1/120 秒以下に刻んで計算し、その間の目標はコマの前の値から直線的に動いたものとする
- 身振りの段階（保持の秒数・中継の時間・関節の時間差）は、実時間ではなく「計算で進めた時間」（上限で切った1コマの経過秒の和）で測る。
  描画が遅く1コマが上限で切られても、腕が届く前に保持が終わらない。ビートだけは音と揃えるため実時間で見る

| 部位 | f | ζ | r | ねらい |
|---|---|---|---|---|
| 腰・背骨・胸 | 1.4 | 0.9 | -0.2 | 大きな体幹はゆっくり、少しだけ予備動作 |
| 首・頭 | 2.2 | 0.6 | 0 | 軽く行き過ぎて戻る |
| 肩・上腕 | 1.8 | 0.8 | -0.3 | 腕を振り上げる前にわずかに引く |
| 前腕 | 2.2 | 0.65 | 0 | 上腕に遅れて、少し行き過ぎる |
| 手 | 2.6 | 0.5 | 0 | さらに遅れて、ふわっと収まる |

### 4.2 根元から先への時間差

身振りが変わったとき、各関節が新しい目標に切り替わる時刻を、根元から先へずらす（体幹 0 → 胸 0.03 → 首 0.05 → 頭 0.08、
肩 0 → 上腕 0.04 → 前腕 0.1 → 手 0.16 秒）。同じ目標でも「肩が先に動き、手が遅れてついてくる」ようになる。

### 4.3 身振りの段階

表情（身振り）が変わると、次の段階を進む。

1. **ストローク** — 身振りのポーズへ（予備動作と行き過ぎは 4.1 で自然に付く）
2. **保持** — ポーズ（身振りごとの `holdS`、既定 2.5 秒）を保つ。保持中も微小な揺れは続く
3. **戻す** — 腕は状態の姿勢（話しているなら軽くひじを曲げた姿勢）へ戻す。体幹・頭・肩は身振りの 60% を残し、
   気分（しょんぼりの猫背など）は続ける。表情（顔）・耳・尻尾はそのまま

同じ表情のまま次の文を読み始めたとき、すでに腕を戻していれば、もう一度ストロークする（文ごとに同じ身振りを繰り返しすぎないよう、
前のストロークから 4 秒以上空いたときだけ）。

### 4.4 腕の経路（中継の姿勢）

腕のねじり（上腕の x）が大きく違うポーズへ移るとき（差が 60 度を超えるとき）は、いったん腕を下ろした姿勢を 0.25 秒ほど
目標にしてから本来のポーズへ向かう。腰に手 ⇔ 胸の前で手、のような切り替えで腕が体を突き抜けないようにする。

### 4.5 声に合わせた強調（ビート）

エージェント（`speech.py`）が、VOICEVOX の `audio_query` から各アクセント句のアクセント核の拍の開始時刻と、
文の中での音の高さ（相対値）を「ビート」として口パクの時系列と一緒に送る。画面は各ビートの少し前から、

- 頭: わずかに上げてから（予備動作）、ビートで小さくうなずく
- 胸: わずかに前へ
- 前腕: 小さく振る（腕が身振りで使われていても、足し算で小さく重ねる）

を重ねる。音の高いビートほど大きく、近すぎるビート（0.35 秒以内）はまとめる。

### 4.6 不規則な揺れと、ときどきの動き

- 規則的な正弦波の揺れを、なめらかなノイズ（値ノイズ）に置き換える（重心の揺れ・頭の向き・呼吸の深さ）
- 待機・聞いている間は、4〜9 秒ごとに重心を左右へ移す、ときどき少しよそを見る、を入れる

### 4.7 確認

Settings のキャラクター一覧の「動きを確認」で、状態・表情・身振りを切り替え、「口パク・強調」ではビートも疑似的に入る。
「身振りをもう一度」で同じ身振りのストロークをやり直せる。

ソフトウェア描画（数fps）の環境でコマ送りを確かめるときは、Playwright の `page.clock.install()` のあと `pauseAt()` で時計を止め、
`runFor()` で進めてはスクリーンショットを撮る（止めないと、描画の遅さで実時間が進んでしまい、段階の途中が撮れない）。
