# 決めたこと

## 静的ファイルのキャッシュと圧縮（2026-11-20）

### 何が困っていたか

リロードが読み込む量の割に遅かった。前は `@fastify/static` の既定のままで、全部のファイルが `public, max-age=0` で圧縮なし。
リロードのたびに全部を問い合わせ（304）、初回は縮めずに送っていた。tailscale serve は圧縮しない。

### 決めたこと

- `/assets/`（Vite が名前に中身の印を付けたもの）は `public, max-age=31536000, immutable`。印の判定は「`/assets/` の下か」だけで行う
- HTML・サービスワーカー・manifest・印の無いもの（アイコン・壁紙・`/fonts/`）は `no-cache`＋ETag・Last-Modified
- 字体は CSS からしか指されないので、組み立てで印付きの写しを `assets/` に作り、HTML をそちらへ向けた。
  前の `/fonts/murecho.css` は外で作られた画面のために残す
- 圧縮は組み立てのときに `.br`・`.gz` を作っておき、サーバーは選んで返すだけ（`preCompressed`）。ホストが非力なのと、
  br の品質11は遅いので、その場では縮めない
- 拡張機能の画面のファイルは組み立ての外（ZIP で持ち込まれる）なので、その場で縮めて覚えておく（br の品質は9）
- API・認証の返事、壁紙の画像（`/api/wallpaper/image`）は変えない

### 試したが入れなかったもの

- `@fastify/compress`（その場で縮める）: 依存が増え、API の返事まで巻き込みやすい。静的ファイルは組み立てで縮めれば足りる
- 字体を Vite の CSS の import に入れる: 本体の CSS と混ざり、小さな woff2 が base64 で埋め込まれる。別に印を付ける方が単純
